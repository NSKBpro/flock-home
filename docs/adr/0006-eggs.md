# 0006 — Eggs: the first mechanic after the core rules

**Status:** Accepted, 18 Oct 2026

## Context

Levels 1–100 used one rule set; only grid size and colour count grew. Both reviews flagged this as a risk. Our working hypothesis (not measured: we have no player data for Flock Home yet) is that a single unchanging rule set gets repetitive by the mid-teens and costs retention there. Basic Launch play data, or a small playtest, should confirm or reject it. The ideas list in GAME_DESIGN.md had six candidates (sleeping bird, egg, pairs, wind, owl, daily). We wanted exactly one before launch, chosen for:

- **Depth:** it should deepen the decision that makes this game different from plain arrow-escape: "this bird is free" vs "this bird is safe to free now".
- **Readability:** understood at a glance on a 360 px phone, without a tutorial screen.
- **Solvability by construction** (ADR 0003) must still hold.

Eggs tie the board to the nest order: some birds cannot leave until a particular nest is filled. That makes "Up next" matter on the grid itself. The others were weaker: a sleeping bird is a smaller version of "blocked"; an owl changes the board's shape but not the decisions; pairs fit badly with nests of three; wind moves pieces every turn and is hard to read.

## Decision

1. **Rule.** An egg sits on a grid cell and blocks birds exactly like a bird does, but cannot be tapped. It hatches, clearing its cell, the moment a nest of its colour is completed. In the engine, egg *k* occupies `occ` as id `birds.length + k`, so every existing ray check treats it as a blocker; `resolveLite` calls `hatch()` before the completed nest is replaced. The page hatches at the same point in `completeNest`, so page and engine stay in step (checked move by move by `npm run ui`).
2. **Level format.** An optional sixth field in the encoded level: `R,C,queue,birds,open[,eggs]`, three characters per egg (row and column in base 36, colour). Levels without eggs encode exactly as before.
3. **Placement keeps levels solvable.** After a candidate's construction order is verified, `placeEggs` adds eggs. An egg of colour *c* may sit on cell X only if every bird whose flight path crosses X leaves, in the construction order, after the first nest of colour *c* is completed. Only eggs that block at least one bird are placed, at most one per colour, never the first or last nest's colour. The order is then re-simulated with the eggs in place. Needs one open nest (ADR 0005).
4. **Introduction.** No eggs before level 12, which comes after the first Storm and its breather; levels 1–11 are unchanged byte for byte. Then one egg, one more every 20 levels up to four; Storms get one more and breathers one fewer. Level 12's coach line explains the rule. One-time tips appear the first time a bird is blocked by an egg and the first time an egg hatches. A daily puzzle with eggs shows the explanation once if the player has not reached level 12.
5. **New dead end.** With eggs, a player can reach a state where no bird can move at all: every remaining bird is blocked, while the nest that would hatch the egg is still waiting. More perches cannot help, so this shows a "No bird can fly" screen that offers Undo (a normal booster use) or Try again, not Keep going. Bots count it as a loss, so it is part of the measured difficulty.

## Consequences

- Levels 12–100 were regenerated, so their layouts changed. This is harmless before launch, but notes from earlier playthroughs of those levels no longer apply. Difficulty is validated as before (ADR 0005, large independent samples).
- The daily puzzle draws from levels 15–80, so dailies now include eggs.
- The level string grows by three characters per egg. The format stays backward compatible: old strings decode unchanged.
- Any future mechanic follows the same pattern: rule in the engine, placement that preserves the construction order, introduction on a fixed level with one coach line and one-time tips, and checks in `npm test` and `npm run ui`.
- Whether eggs make players stay longer is a hypothesis. Playtests and Basic Launch data decide whether to keep them and whether to add the next mechanic.
